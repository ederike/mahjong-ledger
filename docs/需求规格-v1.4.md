## 0.0 v1.4 变更（相对 v1.3）：买马 → 摸马，张数随有无鬼 4↔6

用户纠正：**「我说的马不是买马，是摸马，有鬼摸四张，没鬼摸六张」**。两处修正：

1. **术语**：是「摸马」（胡牌后从牌墙摸固定张数的马牌，按牌面定位座位），不是「买马」。此前文档/口头用了「买马」，全部改为「摸马」。
2. **张数规则（实质变更）**：此前固定每局 4 张马，现改为**随本局有无鬼动态变化**：

| 有无鬼 | 摸马张数 | 计分基数 |
|---|---|---|
| 有鬼 | **4 张** | `times × 底分 2` |
| 没鬼（硬胡） | **6 张** | `times × 底分 2 × 2` |

实现要点：
- **计分引擎内核零改动**。`scoreRound()` 本来就是遍历马牌数组逐张结算，不假设张数；只新增一条机械校验「本局录入马牌数 ≤ 该局摸马张数」，超张数直接报错。
- **单一真相源**移到 `rules.ts` 的 `horse.countByGhost = {withGhost:4, withoutGhost:6}`，并导出 `horseCountFor(hasGhost)`；`score.ts` 校验、`parse.mjs` 解析上限与 LLM 提示词、前端录入框数量全部读它，不再有硬编码 4。
- **前端动态切换**：记分页「有无鬼」按钮切换时，摸马录入框实时 4↔6，保留已填马牌、按需补框/截断；6 张时由 4 列改 3 列 2 行布局。
- **语音 / LLM**：提示词写明「有鬼摸 4、硬胡摸 6，只把中马的牌面放进 horses」，解析上限按本局 `hasGhost` 动态截断并如实提示。
- **存量数据安全**：账本 append-only，落账时冻结四家净分，重放只累加 `net`、不重新算分，故历史房间数据不受张数规则变化影响（已在线上验证）。
- 新增算例：有鬼摸满 4 张、硬胡摸满 6 张逐张结算仍零和、超张数（有鬼 >4 / 硬胡 >6）被拦截、硬胡恰好 6 张合法。

## 0. v1.2 变更（相对 v1.1）

用户纠正：**「翻倍底分是 2，鸡胡就是底分 2」**。v1.1 把杠分的「N 倍底分」擅自按 1 分算，与表格的 2 分裂成两个单位，是错的。

| 项 | v1.1（错） | v1.2（正确） |
|---|---|---|
| 底分 | 1 分（仅用于杠分） | **2 分**，与鸡胡分数同源 |
| 表格数值来源 | 硬编码 2/4/8… | **底分 2 × 倍数 1/2/4/6/8/10/12** 生成 |
| 硬胡 | 硬编码 ×2 | `hardMultiplier: 2` 统一控制 |
| 点杠 3 倍底分 | 3 分 | **6 分** |
| 补杠 1 倍底分 | 每家 1 分 | **每家 2 分** |
| 暗杠 2 倍底分 | 每家 2 分 | **每家 4 分** |

规则配置现为**单一真相源**：`BASE_UNIT = 2`、`HARD_MULTIPLIER = 2`、各档 `times`；改这三处，整张算分表与杠分同步变化，无需手改 14 个数字。

## 1. 最终锁定口径

| 维度 | 结论 |
|---|---|
| 玩法 | 广东麻将，按用户规则图 |
| **底分** | **2 分**；鸡胡有鬼 = 1 倍底分 = 2 分 |
| 计分 | 系统按「用户报的胡法档位 + 有无鬼 + 本局摸马牌面」自动算分，**算出后给用户确认和修改** |
| 牌型判定 | **系统不判定牌型、不判定叠加**，只做「报档位 → 查表 → 算分」 |
| 胡牌方式 | **无点炮**，只有自摸（及抢杠胡）；三家各付 1 份，赢家收 3 份 |
| **摸马** | **有鬼摸 4 张、没鬼（硬胡）摸 6 张**；录入的每张马牌 = 该张中马，按牌面映射座位，中马者额外付赢家 1 份该局胡法分数；多匹叠加；中马者=赢家本人不计 |
| 杠分 | 立即结算、独立流水，不进胡牌番；「N 倍底分」按底分 2 计 |
| 数据共享 | 后端 + SQLite 最小数据库，**所有人都能记分**（事件溯源账本） |
| 主场景 | 手机优先 |
| 首版范围 | 记分 + 自动结算 + 历史统计 |

## 2. 计分规则（图中明确给出，已放大核对）

|---|---|---|---|

### 2.2 其他规则

- 鸡胡只能自摸或抢杠胡；大胡可自摸、抢杠胡
- 可碰、可杠、不可吃牌
- 鬼牌 = 每局翻牌点数 +1；可代任意牌、不能打出
- 胡牌时手中无鬼牌 = 硬胡，倍数 ×2
- 杠牌立即结算（**底分 = 2 分**）：

| 类型 | 原文 | 结算 |
|---|---|---|
| 点杠（他人打出第 4 张） | 收放杠者 3 倍底分 | 放杠者付杠者 **6 分** |
| 补杠（已碰出后再摸到第 4 张） | 收其他玩家各 1 倍底分 | 其余三家各 **2 分** |
| 暗杠（自己摸到 4 张） | 收其他玩家各 2 倍底分 | 其余三家各 **4 分** |

- 马牌 → 座位（以庄家为起点逆时针）：

| 座位 | 对应马牌 |
|---|---|
| 庄家本家 | 万/条/筒 1、5、9，东风 |
| 庄家下家 | 万/条/筒 2、6，南风、红中 |
| 庄家对家 | 万/条/筒 3、7，西风、发财 |
| 庄家上家 | 万/条/筒 4、8，北风、白板 |

## 3. 计分算法（已代码化）

设 `base` = 该胡法档位分数 = `times × 底分 2`（硬胡再 ×2）；`horseCount` = `horseCountFor(hasGhost)`（有鬼 4 / 没鬼 6）。

1. **胡牌主分**：三个输家各 `-base`，赢家 `+3×base`
2. **摸马**：录入马牌数必须 ≤ `horseCount`，超出直接报错；每张马牌按庄家映射到座位；若中马者 ≠ 赢家，该座位再 `-base`、赢家 `+base`；若中马者就是赢家本人 → 自己付自己，**不计**
3. **杠分**：按类型独立记，`倍数 × 底分 2`，不随 `base` 缩放
4. **手改覆盖**：确认页可直接给四家最终净分，覆盖自动结果，保留自动值供对比
5. **零和不变量**：四家净分之和必须为 0，代码内断言

## 8. v1.3 语音 / LLM 记分

**需求**：说一句话（或语音转成的文字），系统自动完成记分。

### 8.1 架构铁律

> **LLM 只做「自然语言 → 结构化字段」，绝不产出分数。**
> 分数一律由已验证的纯函数 `scoreRound()` 计算，并强制零和断言。
> 理由：模型会幻觉、可能算错、可能不零和，一旦让它直接吐分数，账本就不可信。

链路：

```
语音/文字 → POST /api/rooms/:code/parse
          → parseRound()：LLM 抽取 JSON 或规则解析
          → validateAndNormalize()：闭集校验 + 归一化
          → normalizeInput() + scoreRound()（复用已验证内核；v1.4 仅加一条「马牌数 ≤ 摸马张数」校验）
          → 返回 { input, detail }（只预览，不落账）
          → 前端展示解析说明 + 四家净分
          → 用户「确认落账」/「手动调整」→ POST /events（既有流程）
```

v1.3 接入 LLM 时，`score.ts` / `settle.ts` / `store.mjs` 均未改动，计分内核与 LLM 完全解耦。
v1.4 摸马张数规则变更时，`settle.ts` / `store.mjs` 仍未改动；`rules.ts` 改为张数配置真相源、`score.ts` 只加一条张数机械校验，计分与结算逻辑不变。

### 8.2 两路解析

| 模式 | 触发 | 行为 |
|---|---|---|
| **LLM 模式** | 已配置并启用 | OpenAI 兼容 `/chat/completions`，输出严格 JSON：`winner / pattern / hasGhost / horses / gangEvents` |
| **规则模式** | 未配置、已停用、或 LLM 连接失败 | 确定性关键词抽取（昵称/方位/胡型别名/有无鬼/马牌/杠分），界面如实标注 |

- LLM 输出**全部二次校验**：胡法必须是 23 个别名之一、座位必须是 E/S/W/N、马牌必须可映射、点杠必须有放杠者、马牌数 ≤ 本局摸马张数（有鬼 4 / 没鬼 6，提示词写明，解析再动态截断）。非法输出直接报错让用户重说或手填，不静默吞掉。
- LLM 连接/格式失败 → **降级规则模式并在界面显示降级原因**；结构化校验失败不降级。
- 口述直接说「中马的是南家」这类座位时，按当前庄家反推等价马牌牌面（庄家 E 时 东/南/西/北 → 1万/2万/3万/4万）。
- 无鬼/硬胡判定采用**否定优先**，避免「没有鬼」被误判为「有鬼」。

### 8.3 语音输入

两条入口都支持，打牌现场以第一条最可靠：

1. **手机输入法的语音转文字** → 直接出文字进输入框（国内可用、零权限、零成本）。
2. **网页内「点一下说话」** → 浏览器 `SpeechRecognition`（`zh-CN`）；浏览器不支持时按钮自动隐藏并提示改用输入法。

### 8.4 配置与安全

- 密钥**只存服务端** `data/llm-config.json`，GET 接口不回显（只返回 `hasKey`），不写进前端代码或链接。
- 网页「记分 → ⚙ 设置」填一次：服务商（DeepSeek / 通义千问 DashScope / 自定义 OpenAI 兼容端点）+ 接口地址 + 模型名 + API Key，可「测试连接」、可一键停用退回规则模式。
- 环境变量 `MJ_LLM_API_KEY` / `MJ_LLM_BASE_URL` / `MJ_LLM_MODEL` 优先（供本地部署），此时页面只读。
- 配置路径可用 `MJ_LLM_CONF` 外置（联调时与线上隔离）。
- **边界**：`sharecode` 是目前唯一的访问控制，任何拿到链接的人都能使用该密钥。个人牌局工具可接受；若要公开分发需加鉴权。
